### HIGH：账户 / 持仓 / 交易关系的事实依据

**找到的证据：**Empower 将账户、账户下持仓、现金余额及可编辑成本分开呈现；无公开代码的持仓允许手填数量和价格。GnuCash 则把每种股票建为独立证券子账户，证券余额以份额计，新买入对应现金账户流出，历史已有份额可从期初余额建立。**因此“持仓必须是一张独立表”并不是共同事实。**[证据 / HIGH：[Empower 持仓][E-manual]、[无代码持仓][E-private]、[GnuCash 证券账户][G-setup]、[买入/期初][G-buy]]

**沿用的证据：**GnuCash 公开 SQL 的账户表没有当前余额字段，金额在 splits、余额由引擎提供；这不排除缓存。Monarch 同步账户新增手动交易不改同步余额；YNAB 子交易及 GnuCash 分录支持转账和支出共用对象形态，但业务账户类型不同。以上来自 PR #2 的对象模型部分，不能推出 New money 必须做复式账本。[既有证据 / HIGH：[固定版本][L-ledger]]

### MEDIUM：仅供建模讨论的账户 / 持仓 / 交易口径

以下为**建模建议 / MEDIUM**，不是竞品共识、表结构或已确认规格；证据基础见前述 HIGH 部分。

| 概念 | 建议口径与边界 |
| --- | --- |
| 账户 | 表示资产所在处或管理边界。一个券商账户可同时有现金和多种证券；其总余额如果已含证券，不能再与证券市值相加。配置组合另表示被纳入比较的范围，未必等于一个账户。[依据：[E-manual]、[G-setup]] |
| 持仓是不是独立实体 | 领域上应能独立指认「某账户、某标的、某时点的持有状态」；历史齐全时数量可由交易推导，冷启动时也可直接输入期初状态。跨账户同标的可汇总权重，但应保留各自数量/成本来源。是否独立存储不在本文决定。[依据：[E-manual]、[G-buy]] |
| 交易 | 是改变状态的事件，区分买卖、出入金、分红、费用、份额调整；一次买入同时改变现金与证券，不能再当消费减一次总资产。期初快照、估值变化、真正买入是不同来源，不伪造历史交易。[依据：[G-buy]、[L-ledger]；具体事件口径属建议] |
| 成本与市值谁是导出量 | 历史完整且方法固定时，数量和剩余成本由交易/期初推导，平均成本=剩余成本÷数量，市值=数量×对应估值价格。只有当前总市值时，成本不可反推，应为未知；手填成本可作为带来源的期初值。不能靠涨跌倒改成本。[依据：[E-private]、[G-buy]、[G-sell]] |
| 现金边界 | 投资账户的可用现金独立计入现金桶；生活备用金是否在配置分母由本人界定。基金内部现金若没有做穿透，就包含在基金市值内，不能再重复加到现金桶；将“账户”整体和其持仓同时计入也会重复。[依据：[E-manual]；穿透边界为推断] |
| 指数与持仓边界 | 指数是观察对象/基准，不直接产生持仓；实际持有的是对应基金、ETF 等标的。关注一个指数不等于把它加入当前资产权重，目标权重也不等于跟踪指数的成分权重。[推断；依据：[E-portfolio]、[D-intro]] |

**多次买入的合成例子（推断 / MEDIUM，方法假设须由成员确认）：**若选择移动加权平均并将买入费用计入成本，买 10 份×100、费用 10，再买 20 份×120、费用 20，则数量 30、成本 `1,010+2,420=3,430`、平均成本约 `114.3333`。价格 110 时市值 `3,300`，与成本独立。按该方法卖出 6 份，移走成本 `686`，余 24 份、成本 `2,744`；若售价 130、卖出费用 6，则净回款 `774`、该次已实现差额 `88`。中间计算保留精度，最终显示再舍入。

这不是唯一成本法。GnuCash 文档明确其自动 lot 连接采用 FIFO，组合报告还支持 Average/FIFO/LIFO；手续费在不同路径有不同处理限制。不能把简单加权均价宣称为统一券商成本或税务成本；部分卖出、现金分红、分红再投、份额拆合、跨账户转移都可能让“累计净投入÷当前份额”失真。若只做当前配置，数量/市值足够起步，缺成本不应阻止权重计算，也不应显示虚假的盈亏。[证据 / HIGH：[卖出与成本方法][G-sell]；建模推断 / MEDIUM]

**收益边界：**仅有首日和今天市值，不足以区分新增本金与投资回报。Empower 明确其表现计算依赖余额与出入金完整性；You Index 则把当前持仓向历史外推，并不等于个人实际历史。因此快照 MVP 可以报告配置变化，不应据此宣称准确跑赢标普 500。[证据 / HIGH：[表现差异][E-performance]、[You Index 定义][E-you]；产品取舍推断 / MEDIUM]

## 主要风险与反证

### 什么情况下这个判断是错的

| 本文判断 / 置信度 | 哪种反证会推翻它 | 能尽早观察的信号 |
| --- | --- | --- |
| 手填快照足以验证个人配置价值 / 推断 MEDIUM | 本人的账户太多，单次更新已不可接受，或不更新就无法信任差额 | 第一次从自己的资产清单填写时，多次漏填、反复对账，或明确表示下次不会再更新；记录耗时和遗漏原因，不预设通用合格分钟数。 |
| 目标偏离能帮助下一步动作 / 推断 MEDIUM | 本人还没有稳定目标，只关心指数价格/估值；或其“配置”实际指每月投入比例 | 无法给出合计 100% 的资产目标；看到超配后只想修改目标消除提示，或认为投入比例就是当前市值比例。 |
| 指数关注与配置应分开 / 推断 MEDIUM | 本人确实希望估值变化动态改变目标，并能说明一致规则 | 每次查看指数都要求重设目标；应补查动态规则而非直接复制温度或黑板报策略。 |
| 定期复盘或越界提示可能促成回访 / 推断 LOW | 用户持续只在外部执行扣款，从不需要回来；社区内容才是其唯一目的 | 问最近一次打开竞品/表格的实际原因，无法说出要处理的资产问题；一天内只能得到动机线索，不能证明留存。 |
| 简化成本可暂不阻塞配置 / 推断 MEDIUM | 本人首要问题是税务批次、精确收益归因或“是否跑赢指数” | 首次讨论即要求历史出入金、分红、汇率和卖出批次；此时当前快照不足，应重新评估范围。 |

**证据风险 / HIGH：**官方教育文章说明规则，不等于 2026 当前所有客户端流程；雪球教程/FAQ存在上限冲突，且慢补仓例子较旧；蛋卷估值详情正文抓取有限，仅有官方索引，未验证完整当期权限。网页可读也不代表用户愿意使用。上文已逐项降级，不拿营销“欢迎/常用”等措辞证明留存。[依据：[X-guide]、[X-oldfaq]、[Q-cover]、[D-detail]]

**范围与误读风险 / 推断 MEDIUM：**只选部分账户会得到“该配置范围”的权重，不是家庭全部资产；过期估值、未分类标的、基金穿透重复和币种错配可能比界面表达造成更大误差。提醒可提示核对，不能把缺数据变成买卖指令。本文无竞品留存率、需求规模、个人付费意愿的可靠公开证据，也未对投资策略收益或合规作判断。[依据：[E-classify]、[E-performance]与本次证据缺口]

## 下一步最小验证动作（一天内能做完）

这是一组可在一天内完成的验证实验，**不是开发排期、优先级或验收标准**。[研究建议 / MEDIUM]

1. **请 Mika 协调本人提供一份脱敏资产清单与目标。**只需账户代称、资产/现金、数量或市值、估值日期及是否纳入配置；不索要密码或券商连接权限。询问最近一次打开投资工具的具体原因，确认其配置指存量权重还是新增投入比例。拿不到本人输入时只做下述合成实验，需求结论保持未知。
2. **用纸面或静态表格算三个场景：**空仓首次输入；股涨导致偏离；新增资金补低配。用前述 70/20/10 和新增 20 的例子复核百分点/金额。再加入“一个券商余额已含证券”和“某持仓缺价”两个反例，确认不会重复统计或显示零偏离。
3. **让本人读两种表达并说下一步：**同一资产同时给目标/当前/百分点，以及对应金额差；允许答案是“先核对数据”或“不操作”。记录误读、输入负担和其需要的提醒时机，不以点击/喜欢作为成功证据。若无本人参与，Mika 记录为待验证，不伪称已通过用户测试。
4. **记录可推翻的结果：**若目标不稳定，收缩到资产盘点与指数关注再研究；若每次都要精确收益，明确快照不足；若能解释差额并指出下一次会为什么回来，才支持继续验证此闭环。真正留存仍需后续重复使用数据，一天无法证明。

需要真实资产清单或访谈时由 Mika 协调；这是研究输入缺口，不要求登录竞品、购买资料或扩大到行情与合规调查。[权限与方法边界]

## 给 New money MVP 的建议取舍

1. **保留“本人目标 + 当前资产快照 + 差额解释”这个最小闭环。**允许成本未知，清楚列出账户范围、现金、分类及更新时间；先验证能否决定新钱去向或明确不操作。必须的依据是可解释的当前状态，不是全量历史流水。[建议 / MEDIUM；[E-manual]、[Y-rebalance]、[E-performance]]
2. **保留少量指数关注，按已验证覆盖展示指标。**把市场状态与个人配置并列，标日期、指标定义和缺失；PE/PB 分位、定投成本、回撤不必一并齐全。现阶段不据此自动生成个人目标、收益对标结论或自动买卖；是否采用动态目标由本人拍板。[建议 / MEDIUM；[Y-data]、[D-detail]、[E-you]]
3. **暂不复刻服务规模才需要的设施。**社区排行/主理人生态、投顾问卷与策略库、跨券商自动聚合、扣款交易和复杂成本批次，不是单人 Web 验证差额价值的必要条件；提醒的触发与频次先取得本人真实场景再决定。它们在原产品有服务对象，但本次没有证据证明自用也需要承担相同复杂度。[建议 / MEDIUM；[X-feature]、[E-link]、[E-alt]、[D-agreement]、[G-sell]；商业与范围取舍需要成员本人拍板]
