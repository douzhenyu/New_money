# 个人理财 MVP 定义

> **以下三条是假设，不是结论**，可随时推翻；被推翻时，受影响功能在「待成员拍板」里标注。
>
> 1. **平台**：先做响应式 Web，手机浏览器可用；原生 App 推迟到需求验证之后。
> 2. **使用者**：先给养乐多不二自己用，不做账号体系、不做多租户。
> 3. **数据**：本地优先（浏览器 IndexedDB），提供导入导出；云同步推迟。

## 一句话定位

给自己用的手机记账本：付完钱十几秒记一笔，随时看清这个月花了多少、花在哪。

## 核心场景

1. **刚付完钱，站在收银台前**：只想马上记下来，但现有 App 要先选账户、选标签、看广告——于是不记了，月底对不上账。
2. **月中想确认还能花多少**：知道有几笔大额，却看不到本月合计与分类占比，只能翻流水心算。
3. **换手机或清了缓存**：记录跟着没了，也导不出来，前几个月白记。

## MVP 功能集

| # | 功能 | 验收标准（Vera 可独立判定） |
|---|---|---|
| 1 | 快速记一笔：金额、分类、日期、备注 | 填金额、选分类、确认日期后保存，列表顶部立即出现该记录，本月支出合计同步增加；日期默认今天；金额为空、为 0 或非数字时保存按钮不可用。 |
| 2 | 本月概览：收入 / 支出 / 结余 | 进入首页即显示三个数字，与列表中同月记录逐笔求和一致；本月无记录时显示 0，不空白、不报错。 |
| 3 | 流水列表，可改可删 | 列表按日期倒序，可切到任意月份；编辑金额后概览同步变化；删除需二次确认，确认后该条消失且合计减少，取消则不变。 |
| 4 | 分类：预置常用分类 + 自定义增删 | 首次启动自带 ≥8 个分类；新增后无需刷新即可在记一笔的分类选择器出现；删除仍被记录引用的分类时被阻止并提示；删除无引用的立即生效。 |
| 5 | 数据可带走：导出 / 导入 JSON | 导出单个 JSON 文件，含版本号与条数；导入后条数、各月合计与原数据完全一致；导入前说明是覆盖还是合并，并可取消。 |

## 明确不做（本版砍掉，以及为什么现在砍）

- **账号、云同步、多端**：还没有第二台设备要同步，眼下只增加登录与冲突合并成本；先验证「我会持续记账」。
- **自动导入银行 / 微信 / 支付宝账单**：格式与授权成本高，且要先证明手动记一笔不是瓶颈。
- **预算、趋势报表、多币种、资产净值**：记录不到百条时不产生洞察，只会推迟上线。
- **原生 App、可安装离线包**：响应式 Web 已覆盖手机场景，等需求验证后再投。
- **视觉与主题打磨**：不阻塞 MVP 成立；骨架定了交给 Iris。

## 关键风险（按可能性排序）

1. **坚持不下来**（最可能）：记三天就停，账目再准也没用。缓解：一笔 ≤3 步、默认值一键保存；上线后自己连用两周再判断。
2. **分类选不出来**，记账中途放弃。缓解：预置分类少而常见，并保留「其他」。
3. **本地数据丢失**（清缓存、换浏览器、无痕模式）。缓解：首次启动说明数据只在本地；每 30 天提示导出。
4. **手机输入体验差**：金额键盘、日期选择器各浏览器差异大，可能拖慢一笔录入。需真机验证。
5. **假设被推翻**（要做多用户或云端）：存储与数据模型返工。缓解：读写收敛在一个数据层，便于整体替换。

## 待成员拍板

1. 主要解决「知道钱花哪了」，还是也要管收入与资产（工资、理财、负债）？现按收支记账定义。
2. 记账颗粒度：每笔都记，还是只记大额、小额打包？这决定分类数量与录入步骤。
3. 需要多币种或海外消费吗？不需要就先只做人民币。
4. 「数据只在本地浏览器」能接受吗（换设备或清缓存就没了）？还是必须能导出到手机文件才算安全？
5. 只给你自己用，还是也给家人用？给别人用则账号体系得提前，MVP 范围会变大。

回复「按这个做」视为确认；要改哪条直接说。
